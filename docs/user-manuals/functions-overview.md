# Functions overview

This guide lists autoloaded shell functions in `~/.config/zsh/functions/` (repo: `config/zsh/functions/`).
They are available after the Zsh framework starts. You do not need manual registration.

## Daily commands

| Function | Purpose |
| --- | --- |
| `zsh-doctor` | Report loaded modules, compiled files, PATH issues, function load state, completion state, and framework health. |
| `node-doctor` | Report `mise`, Node, npm, pnpm, package-manager paths, project runtime pins, and duplicate Node candidates. It does not change state. |
| `restart-zsh` | Replace the current shell with a fresh Zsh process. |
| `zsh-profile` | Restart Zsh with startup profiling enabled. |
| `scripts/sync-home.zsh` | Copy repo config into `~/.zshenv`, `~/.config`, `~/.local`, Colima and LaunchAgents. Unchanged targets are skipped, and replaced ones are backed up to `~/.local/state/dotfiles/backups/`. Use `--dry-run` first. |
| `colima-setup` | Run the Colima and Docker reinstall helper from an interactive shell. |

## Zsh maintenance

| Function | Purpose |
| --- | --- |
| `zsh-recompile` | Remove adjacent `.zwc` files under the Zsh config root and restart Zsh so modules compile again. |
| `zsh-rebuild-completions` | Remove and rebuild the Zsh completion dump and compiled completion cache. |

## Colima and Docker

| Function | Purpose |
| --- | --- |
| `colima-start` | Run `colima start` and pass through all arguments. |
| `colima-status` | Run `colima status` and pass through all arguments. |
| `colima-stop` | Run `colima stop` and pass through all arguments. |
| `colima-test` | Test the repo in a throwaway Ubuntu container on the `linux-vm` Colima VM before syncing (runs `scripts/test-in-colima.zsh`). |

See [Colima Docker](colima-docker.md) for host/container boundaries and common checks.

## Local AI wrappers

| Function | Purpose |
| --- | --- |
| `codex-local` | Run `codex` with AI secrets loaded through the Keychain wrapper. |
| `claude-local` | Run `claude` with AI secrets loaded through the Keychain wrapper. |
| `goose-local` | Run `goose` with AI secrets loaded through the Keychain wrapper. |

| `prompthub-keys` | Run PromptHub key management from the PromptHub app virtual environment. |

## Headroom deployments

| Command | Purpose |
| --- | --- |
| `headroom-deploy <action> [profile] [-v]` | `start`, `stop`, `restart` or `status` run `headroom install <action> --profile …`. `health` checks the profile's `health_url`, and `logs` follows `runner.log`. Tab completion covers actions and profiles. |
| `hr-<short>-<action>` | Aliases, e.g. `hr-lms-restart` = `headroom install restart --profile visualval-lmstudio`. Shorthands: `lms` → `visualval-lmstudio` (:8788), `init` → `init-visualval` (:8787). Actions: `start stop restart status health logs`. |

Shorthands live in `HEADROOM_PROFILE_ALIASES` in `apps.d/20-headroom.zsh`.

## Common pitfalls

- Do not edit adjacent `.zwc` files. They are generated bytecode.
- Do not put large command bodies in app modules. Add a function file under `.config/zsh/functions/` instead.
- Do not assume a repository edit changes the active shell. The active tree is copy-installed at `~/.config/zsh/` by `scripts/sync-home.zsh`.
- Do not store secrets in these function files. Use the Keychain helpers.
